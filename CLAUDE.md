# Slug Equals Title (Craft CMS plugin)

Keeps the slug of entries equal to their title. Per section or entry type by default (plugin settings, overridable in `config/craft/slug-equals-title.php`), and per entry with a switch next to the slug field in the editor. Four files do the work: `src/SlugEqualsTitle.php` (events, the switch for both editors, its inline script), `src/Slugs.php` (what is enabled for an entry, the remembered choices in `slugequalstitle_elements`), `src/Settings.php` + `src/SettingsForm.php`, `database/migrations/Install.php`.

## Branch 4.x: Craft 6, native
This branch is the native Craft 6 port: a Laravel plugin (`craftcms/cms` 6, PHP 8.5 at `/opt/homebrew/opt/php/bin`), no Yii2 adapter, no `\Craft::$app`, no `craft\` namespaces. Entries only: Craft 6 has categories and Commerce products only through compatibility layers, and the user wants none in between (3.x supports them on Craft 5). 3.x is the Craft 5 version; `UPGRADE.md` lists the public changes. 4.0 requires 3.1.0 first (`minVersionRequired`): the table and the UID settings are 3.1's, so this branch ships only the install migration. Settings keys of 3.x that no longer exist (`enabledCategoryGroups`, `enabledProductTypes`) are ignored by Craft's `setAttributes`.

## How it works
- `ElementSaving` (before Craft validates): when the form's switch (`SlugEqualsTitle::PARAM` body param) says so, or without it a web save whose request names the entry (`elementId` or `entryId` = its canonical id: the edit page posts only what changed, to `entries/save-entry`, `elements/save` or through a provisional draft, so an unchanged switch is absent) or the console follows the remembered choice, `$element->slug = ElementHelper::generateSlug(title, null, site language)`. Craft's own slug and URI validators run after the event: they normalize it and make the URI unique (`-2`). Revisions, nested entries (no section), empty titles, and web requests that do not name the entry (index actions, other elements saved along by a plugin) are left alone.
- `ElementSaved`: a posted switch is remembered per element (`DB::table()->upsert`, one row per element, rows cascade with the element), only for the element the form is about (`elementId` = the element's canonical id), not again while propagating to other sites. A draft falls back to its canonical element's choice until it makes its own.
- Two editors: the Inertia editor (edit pages) renders the sidebar as a Form; `ElementEditorPayloadResolving` gives its payload, and the plugin resolves a `Lightswitch` field through `FormResolver` and splices it into `sidebarForm` right after the `slug` node (none when the type hides its slug field: `showSlugField`). `SlugEqualsTitle::JS_EDITOR`, registered in `boot()` for every CP request (Inertia swaps pages without a reload), hides that field and wraps the slug field's `<craft-input>` in a flex row (`div.slug-equals-title-row[slot=input]`) with an “Overwritten by title” note and the field's `<craft-switch>`; while on, the input is hidden and the note shown. A `MutationObserver` on the document re-applies it after re-renders, and a re-rendered switch (a new `<craft-switch>` back in its hidden field) replaces the stale one in the row. Lion's `prefix`/`suffix` slots were tried first: they render as bordered boxes and stack. The sidebar form is not refreshable (no `refresh` on its renderer), so a reactive control could not do this server-side. The legacy editor (slideouts) uses `ElementMetaFieldsHtmlResolving`: the switch as HTML (`Cp\Components\Lightswitch`, a `<craft-switch>` web component) in a hidden holder, and `SlugEqualsTitle::JS` (via `HtmlStack::js`) moves it into the slug field's input container, next to the input; while it is on, the input is disabled and hidden and an “Overwritten by title” note takes its place.
- Settings (`PluginSettings`, a property hook normalizes the list) hold UIDs (the settings page) or handles (the config file, settings saved before 3.1); `Slugs::settingKeys()` lists every value that means an entry's type, including `section:entryType`. Craft merges `config('craft.slug-equals-title')` over the stored settings when it creates the plugin. The settings page is a `Form` (`SettingsForm`): one `Choice` list of the sections, a section's entry types under it; when the config file sets the list it is disabled with a warning, and its options take the handles the file names so they show as ticked (Craft fills the form from the settings as they are).

## Working on it
- `dev/dev.sh` creates/starts a Craft 6 dev project in `../craft-slug-equals-title-dev6` (port 8130; PostgreSQL via Homebrew; `DB_DRIVER=mysql PROJECT_DIR=… PORT=8131` for a second one). `setup|up|serve|stop|seed|smoke|e2e|ui|screenshots|reset|ci|coverage|typecheck`. Scripts boot the app with `dev/craft.php`. The seed (`dev/seed.php`) builds the demo site "Transit": sites "Transit" and "Transit (Deutsch)" (handle `de`), the sections News (on by default), Pages (off; two entry types, "About us" keeps its slug) and the single Home (its entry type hides the slug field), a Matrix field with titled blocks on Pages. No config file: the HTTP suite writes `config/craft/slug-equals-title.php` for its override checks and removes it again. `.env` sets `CRAFT_LIMIT_AUTO_SLUGS_TO_ASCII=true` so the German site's transliteration is testable.
- Three suites, run after every change, ideally on both databases: `dev/dev.sh smoke` (`dev/smoke.php`, the console: defaults, entry types and handles, remembered choices, resaving, uniqueness, sites, drafts, revisions, empty titles, nested entries, install/uninstall), `dev/dev.sh e2e` (`dev/e2e.php`, the control panel over HTTP: the Inertia page JSON of edit pages, `elements/save`, `save-draft`, `apply-draft`, the slideout screen, the revision view, the settings page, the config-file override and the settings save), `dev/dev.sh ui` (`dev/ui.mts`, headless Chrome via `dev/browser.mts`, no packages: the switch after the slug field on the Vue editor, saving, the German site, the settings page). `dev/dev.sh ci` = smoke + e2e + ui and regenerates `dev/TESTS.md`; `dev/dev.sh coverage` = ci with line coverage of `src/` and `database/` (pcov, `COVERAGE_MIN` 100 %). GitHub Actions runs PHPStan (Larastan, level 9; `vendor/bin/testbench about` first) + typecheck, and `coverage` on PHP 8.5 × MySQL/PostgreSQL (`.github/workflows/ci.yml`).
- `dev/targets.php` prints the demo elements' edit paths for the Chrome suites and creates/removes the "UI: …" fixtures (and resets the seeded settings). `dev/dev.sh screenshots` retakes `docs/screenshots/*.jpg` (`dev/screenshots.mts`: the page in a browser window, a ring on the feature, a zoomed inset; `cover.jpg` is three close-ups under the plugin's name).
- Every PHP file declares `strict_types=1`. The dev scripts in TypeScript (`.mts`) run as they are on Node 24; `dev/dev.sh typecheck` checks them. The plugin's own JavaScript stays inline (no build step). Translations: `lang/<lang>` for every language Craft ships (keys are the English strings); a new string needs all 33 files.
- `CHANGELOG.md` has an `Unreleased` section; add user-facing changes there.

## Quirks (found the hard way)
- Several Craft 6 dev projects run side by side on this machine (8090–8095 are taken by others): `serve()` fails when the port is in use, because another project would answer instead. `stop()` kills the server by its command line (the router path names the project) and waits for the port: the PHP built-in server's workers outlive a killed parent. Don't pipe `dev/dev.sh serve|screenshots` into `tail`/`grep` in a tool call: the server's workers hold the pipe and the call never returns; redirect to a file.
- The Vue editor's save posts `elements/save-draft` + `apply-draft` with only the changed values (a delta) and `editorContainerId`; the legacy slideout posts its whole form, namespaced in HTML and stripped on submit.
- Craft 6's lightswitch is `<craft-switch><craft-switch-button role="switch" aria-checked>…<input type="hidden" slot="hidden-input"></craft-switch>`; no jQuery on Craft 6 pages: the inline script uses `addEventListener`. In Chrome tests, `craft-switch-button.click()` toggles it, the Save button is `craft-button[type="submit"]`, and the page stays (Inertia): open it again to read what was stored. A page's Inertia props are in `<script data-page="app" type="application/json">`.
- A disabled Choice control on the settings page still posts its value: the project config may hold what the config file overrides (harmless: the file wins). Don't assert its absence.
- `Plugins::savePluginSettings()` in a bootstrapped script needs `ProjectConfig::saveModifiedConfigData()` afterwards (no app termination).
- `Elements::resaveElements()` takes a query; revisions are queried with `revisionOf()`, nested entries with `ownerId()->fieldId()`; `orderBy('elements.dateCreated', 'desc')`.
- PHPStan (Larastan): type Craft's facades' collections (`/** @var list<Section> */`).
- A Chrome test that opens the site must use this project's port.
