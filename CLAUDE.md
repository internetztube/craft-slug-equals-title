# Slug Equals Title (Craft CMS plugin)

Keeps the slug of entries, categories and Commerce products equal to their title. Per section, category group or product type by default (plugin settings, overridable in `config/slug-equals-title.php`), and per element with a switch in the slug field of the edit page. Four files do the work: `src/SlugEqualsTitle.php` (events, the switch, its inline script), `src/services/SlugService.php` (what is enabled for an element, the remembered choices in `{{%slugequalstitle_elements}}`), `src/models/Settings.php`, `src/migrations/`.

## How it works
- `Element::EVENT_BEFORE_SAVE` on each supported class: when the form's switch (`SlugEqualsTitle::PARAM` body param) or, on the console, the remembered choice says so, the title first loses the stop words of the site's language (`Settings::$stopWords`, one canonical line per language such as `a, and, the` (the same shape as on 4.x, whose settings form shows the model's values as they are); `SlugService::titleForSlug()`: whole words, keyed by language, `de` for de-AT and de-DE alike (Craft keeps them apart, the words do not; a locale key counts as its language), a title of only stop words stays), then `$element->slug = ElementHelper::generateSlug(title, null, site language)`. Craft's own slug and URI validators run after the event: they normalize it and make the URI unique (`-2`). Revisions, nested entries (no section), empty titles, and web saves without the form field (queue jobs, index actions, other plugins) are left alone, as since 1.x: a minor release keeps that.
- `EVENT_AFTER_SAVE`: a form's switch is remembered per element (`Db::upsert`, one row per element, rows cascade with the element). Only for the element the form is about (`elementId` body param = the element's canonical id), so another element saved in the same request by a plugin is not touched; not again while propagating to other sites.
- `EVENT_DEFINE_META_FIELDS_HTML`: Craft appends the event's HTML after its own meta fields, so the switch is rendered there (hidden) and `SlugEqualsTitle::JS` moves it into the slug field's input container, next to the input, locks the slug input while the switch is on, and previews the slug with `Craft.SlugGenerator` (what Craft uses for new entries; the server sets the final slug). The script runs per page and per slideout (`registerJs`, deduplicated per response). A type without a slug field (entry types with `showSlugField` off, product types): the script removes the switch.
- A draft falls back to its canonical element's remembered choice until it makes its own. Slideouts namespace their inputs in HTML and strip the namespace on submit, so the body param name is the same everywhere.
- Settings hold UIDs (the settings page) or handles (`config/slug-equals-title.php`, settings saved before 3.1); `SlugService::settingKeys()` lists every value that means an element's type, including `section:entryType` for one entry type of a section. `m261103_130000_settings_uids` converts stored handles once; its guard reads the YAML's schema version (`get(..., true)`), the Craft pattern for project config changes in migrations, so a deployment that already carries the YAML does not convert twice. Craft merges `config/slug-equals-title.php` into the settings by itself (`Plugins::createPlugin`); the settings page shows overridden lists read-only, with the file's handles ticked.

## Working on it
- `dev/dev.sh` creates/starts a Craft 5 dev project in `../craft-slug-equals-title-dev` (PostgreSQL via Homebrew; `DB_DRIVER=mysql PROJECT_DIR=... PORT=8081` for a second one). `up|serve|stop|seed|smoke|e2e|ui|screenshots|reset|ci|coverage|typecheck`. The seed (`dev/seed.php`) builds the demo site "Transit" (a travel journal; sites "Transit" in English and "Transit (Deutsch)", handle `de`), the sections News (on by default; articles with a hero photo, intro, CKEditor body and topics, so the edit page looks real in screenshots; the photos are the author's own from Unsplash, downloaded on the first seed, a drawn gradient offline), Pages (off; "About us" keeps its slug) and the single Home (its entry type hides the slug field), a Matrix field with titled blocks on Pages, the category groups Topics (on through the config file, read-only on the settings page) and Regions, and with Commerce the product type Clothing (on). `.env` sets `CRAFT_LIMIT_AUTO_SLUGS_TO_ASCII=true` so the German site's transliteration is testable. No front end: the sections, groups and the product type have URLs (for unique URIs) but no template; the control panel is the demo.
- Three suites, run after every change, ideally on both databases: `dev/dev.sh smoke` (`dev/smoke.php`, the console: defaults, remembered choices, resaving, uniqueness, sites, drafts, revisions, empty titles, nested entries, categories, products, the 3.x migration, install/uninstall), `dev/dev.sh e2e` (`dev/e2e.php`, the control panel over HTTP: edit pages, the switch's param through `elements/save`, `save-draft`, `apply-draft`, the slideout screen, the revision view, the settings page), `dev/dev.sh ui` (`dev/ui.mts`, headless Chrome via `dev/browser.mts`, no packages: what a person sees: the switch in the slug field, the locked input and its preview, saving, the slideout, the German site, the settings page). `dev/dev.sh ci` = smoke + e2e + ui and regenerates `dev/TESTS.md` (`dev/tests-md.php`, one sentence per assertion); `dev/dev.sh coverage` = ci with line coverage of `src/` (pcov, `COVERAGE_MIN` 100 %: every line of `src/` runs in a test; delete a guard that cannot trigger instead of excluding it). GitHub Actions runs PHPStan + typecheck and `coverage` on PHP 8.2/8.3 × MySQL/PostgreSQL (`.github/workflows/ci.yml`); keep the two in sync by changing the script, not the workflow.
- `dev/plugins.txt` lists the plugins the dev project installs: Craft Commerce (the product type support) and CKEditor (the demo's body field; the plugin itself needs neither).
- `dev/targets.php` prints the demo elements' edit paths for the Chrome suites and creates/removes the "UI: …" fixtures (and resets the seeded settings). `dev/dev.sh screenshots` retakes `docs/screenshots/*.jpg` (`dev/screenshots.mts`: the page in a browser window, a ring on the feature, a zoomed inset; `cover.jpg`, the README's and the Plugin Store's cover, is three close-ups under the plugin's name).
- `vendor/bin/phpstan` must stay clean (level 9, `phpstan.neon`; Commerce classes are ignored, Commerce is optional). Every PHP file declares `strict_types=1`: cast DB rows and request params at the boundary. The dev scripts in TypeScript (`.mts`) run as they are on Node 24 (type stripping); `dev/dev.sh typecheck` checks them. The plugin's own JavaScript stays inline (no build step).
- `CHANGELOG.md` has an `Unreleased` section; add user-facing changes there. Translations: `src/translations/<lang>` for every language Craft ships (keys are the English strings); a new string needs all 31 files.
- Release: set the version in `composer.json` and the date of the `CHANGELOG.md` entry, commit, then `git tag X.Y.Z && git push origin X.Y.Z`. `.github/workflows/release.yml` publishes the GitHub release with that changelog section as notes (a `-alpha`/`-beta` tag as a prerelease). Never push a tag to try something out.

## Quirks (found the hard way)
- Craft's edit page saves a canonical entry by applying its provisional draft (`elements/apply-draft`) and then redirects to the index; a Chrome test that reads the saved page must open it again. Saving plugin settings redirects to the plugin list.
- A test that changes project config and expects a migration to read it must write the YAML and drop the memoized copy: `saveModifiedConfigData()`, `writeYamlFiles(true)`, `reset()`.
- Project config drops empty arrays: a setting saved as `[]` reads back as `null`; `Settings::setAttributes()` normalizes that (and the `''` of an empty checkbox list, and the `;` placeholder 3.x stored).
- A bootstrapped console script never fires `EVENT_AFTER_REQUEST`, so project config changes (plugin settings) need `ProjectConfig::saveModifiedConfigData()`; `dev/dev.sh` writes the YAML back afterwards (`project-config/write`).
- `Db::batchInsert()` in Craft 5 takes no `$includeAuditColumns` argument (it fills `dateCreated`/`dateUpdated`/`uid` itself).
- Yii's schema cache: after dropping a table in the same process, call `$db->getSchema()->refresh()` before `tableExists()`.
- MySQL on macOS/Windows stores table names lower-case; a dump of 3.x's `slugEqualsTitle_shouldRewrite` imported on Linux is `slugequalstitle_shouldrewrite` (#21). The migration looks for both spellings, one after the other (on macOS both names are the same table).
- The slideout screen is fetched with GET and needs the `X-Craft-Container-Id` and `X-Craft-Container-Type: slideout` headers; its JSON keys are `sidebar`, `content`, `headHtml`, `bodyHtml`, `namespace`.
- A revision is viewed on the edit page with `?revisionId=`; Craft renders the meta fields static (`$event->static`), the switch is then a `noteditable` lightswitch.
- `Craft.LightSwitch` toggles on `mousedown`/`keydown`, not `click`: tests call `$(el).data('lightswitch').toggle()`. It triggers `change` on its element, which the inline script listens for.
- The Claude in Chrome extension's synthetic clicks don't fire DOM events on CP edit pages; check JS handlers through `javascript_tool`.
