# Slug Equals Title (Craft CMS plugin)

Keeps the slug of entries (and, with Craft's Yii2 adapter, categories) equal to their title. Per section, entry type or category group by default (plugin settings, overridable in `config/craft/slug-equals-title.php`), and per element with a switch next to the slug field in the editor. Four files do the work: `src/SlugEqualsTitle.php` (events, the switch for both editors, its inline script), `src/Slugs.php` (what is enabled for an element, the remembered choices in `slugequalstitle_elements`), `src/Settings.php` + `src/SettingsForm.php`, `database/migrations/Install.php`.

## Branch 4.x: Craft 6
This branch is the native Craft 6 port (Laravel, `craftcms/cms` 6, PHP 8.5 at `/opt/homebrew/opt/php/bin`; no Yii2 adapter needed, categories only with it). 3.x is the Craft 5 version; `UPGRADE.md` lists the public changes. 4.0 requires 3.1.0 first (`minVersionRequired`): the table and the UID settings are 3.1's, so this branch ships only the install migration.

## How it works
- `ElementSaving` (before Craft validates): when the form's switch (`SlugEqualsTitle::PARAM` body param) says so, or without it an editor save (`editorContainerId` in the request: Craft 6's editor posts only what changed, so an unchanged switch is absent) or the console follows the remembered choice, `$element->slug = ElementHelper::generateSlug(title, null, site language)`. Craft's own slug and URI validators run after the event: they normalize it and make the URI unique (`-2`). Revisions, nested entries (no section), empty titles, and other web saves without the form field (queue jobs, index actions, other plugins) are left alone, as since 1.x.
- `ElementSaved`: a posted switch is remembered per element (`DB::table()->upsert`, one row per element, rows cascade with the element), only for the element the form is about (`elementId` = the element's canonical id), not again while propagating to other sites. A draft falls back to its canonical element's choice until it makes its own.
- Two editors: the Inertia editor (edit pages) renders the sidebar as a Form; `ElementEditorPayloadResolving` gives its payload, and the plugin resolves a `Lightswitch` field through `FormResolver` and splices it into `sidebarForm` right after the `slug` node (none when the type hides its slug field: `showSlugField`). The legacy editor (slideouts, the adapter's elements) uses `ElementMetaFieldsHtmlResolving`: the switch as HTML (`Cp\Components\Lightswitch`, a `<craft-switch>` web component) in a hidden holder, and `SlugEqualsTitle::JS` (via `HtmlStack::js`) moves it into the slug field's input container, next to the input; while it is on, the input is disabled and hidden and an “Overwritten by title” note takes its place.
- Settings (`PluginSettings`, property hooks normalize the lists) hold UIDs (the settings page) or handles (the config file, settings saved before 3.1); `Slugs::settingKeys()` lists every value that means an element's type, including `section:entryType`. The settings page is a `Form` (`SettingsForm`): a `Choice` list per element type, a section's entry types under it; a list set in the config file is disabled with a warning, and its options take the handles the file names so they show as ticked (Craft fills the form from the settings as they are).

## Working on it
- `dev/dev.sh` creates/starts a Craft 6 dev project in `../craft-slug-equals-title-dev6` (port 8130; PostgreSQL via Homebrew; `DB_DRIVER=mysql PROJECT_DIR=… PORT=8131` for a second one). `setup|up|serve|stop|seed|smoke|e2e|ui|screenshots|reset|ci|coverage|typecheck`. `YII2_ADAPTER=1` installs Craft's Yii2 adapter (categories); a fresh Craft 6 install has no category tables, the seed adds them (`craft:add-categories-support`) and the second seed pass makes the groups. Scripts boot the app with `dev/craft.php`. The seed (`dev/seed.php`) builds the demo site "Transit": sites "Transit" and "Transit (Deutsch)" (handle `de`), the sections News (on by default), Pages (off; two entry types, "About us" keeps its slug) and the single Home (its entry type hides the slug field), a Matrix field with titled blocks on Pages, with the adapter the category groups Topics (on through the config file, read-only on the settings page) and Regions. `.env` sets `CRAFT_LIMIT_AUTO_SLUGS_TO_ASCII=true` so the German site's transliteration is testable.
- Three suites, run after every change, ideally on both databases: `dev/dev.sh smoke` (`dev/smoke.php`, the console: defaults, entry types and handles, remembered choices, resaving, uniqueness, sites, drafts, revisions, empty titles, nested entries, categories, install/uninstall), `dev/dev.sh e2e` (`dev/e2e.php`, the control panel over HTTP: the Inertia page JSON of edit pages, `elements/save`, `save-draft`, `apply-draft`, the slideout screen, the revision view, the settings page and its save), `dev/dev.sh ui` (`dev/ui.mts`, headless Chrome via `dev/browser.mts`, no packages: the switch after the slug field on the Vue editor, saving, the German site, the settings page). `dev/dev.sh ci` = smoke + e2e + ui and regenerates `dev/TESTS.md`; `dev/dev.sh coverage` = ci with line coverage of `src/` and `database/` (pcov, `COVERAGE_MIN` 100 %). GitHub Actions runs PHPStan (Larastan, level 9; `vendor/bin/testbench about` first) + typecheck and `coverage` on PHP 8.5 × MySQL/PostgreSQL with the adapter, plus `ci` without it (`.github/workflows/ci.yml`).
- `dev/targets.php` prints the demo elements' edit paths for the Chrome suites and creates/removes the "UI: …" fixtures (and resets the seeded settings). `dev/dev.sh screenshots` retakes `docs/screenshots/*.jpg` (`dev/screenshots.mts`: the page in a browser window, a ring on the feature, a zoomed inset; `cover.jpg` is three close-ups under the plugin's name).
- Every PHP file declares `strict_types=1`. The dev scripts in TypeScript (`.mts`) run as they are on Node 24; `dev/dev.sh typecheck` checks them. The plugin's own JavaScript stays inline (no build step). Translations: `lang/<lang>` for every language Craft ships (keys are the English strings); a new string needs all 33 files.
- `CHANGELOG.md` has an `Unreleased` section; add user-facing changes there.

## Quirks (found the hard way)
- Several Craft 6 dev projects run side by side on this machine (8090–8095 are taken by others): `serve()` fails when the port is in use, because another project would answer instead. Don't pipe `dev/dev.sh serve|screenshots` into `tail`/`grep` in a tool call: the server's workers hold the pipe and the call never returns; redirect to a file.
- The Vue editor's save posts `elements/save-draft` + `apply-draft` with only the changed values (a delta) and `editorContainerId`; the legacy slideout posts its whole form, namespaced in HTML and stripped on submit.
- Craft 6's lightswitch is `<craft-switch><craft-switch-button role="switch" aria-checked>…<input type="hidden" slot="hidden-input"></craft-switch>`; no jQuery on Craft 6 pages: the inline script uses `addEventListener`. In Chrome tests, `craft-switch-button.click()` toggles it, the Save button is `craft-button[type="submit"]`, and the page stays (Inertia): open it again to read what was stored. A page's Inertia props are in `<script data-page="app" type="application/json">`.
- A disabled Choice control on the settings page still posts its value: the project config may hold what the config file overrides (harmless: the file wins). Don't assert its absence.
- `Plugins::savePluginSettings()` in a bootstrapped script needs `ProjectConfig::saveModifiedConfigData()` afterwards (no app termination).
- `Elements::resaveElements()` takes a query; revisions are queried with `revisionOf()`, nested entries with `ownerId()->fieldId()`; `orderBy('elements.dateCreated', 'desc')`.
- PHPStan (Larastan): type Craft's facades' collections (`/** @var list<Section> */`), and object shapes for the adapter's models; the `craft\\` namespaces are ignored (optional adapter and Commerce).
- A Chrome test that opens the site must use this project's port; the stale `tail` of a hung call keeps a `dev.sh` process alive (`pkill -f 'dev.sh screenshots'`).
